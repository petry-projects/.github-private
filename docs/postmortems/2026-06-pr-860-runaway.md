# Post-mortem: PR #860 runaway — agents self-triggering (June 2026)

**Status:** resolved (P0 fixes tracked in #926)
**Incident PR:** #860 (closed; re-opened from a fresh rebased branch)
**Provenance:** originally written in PR #924; that PR was closed in favor of
issue #926 as the single source of truth, and this doc is re-added alongside the code fixes.

---

## Summary

PR #860 — a routine `[Phase 2]` LSP change — ran away to **378 commits and 1,582
comments** over four days for a **net 18-file, +524/−982 diff**, and never
converged (`mergeable_state: blocked`). The entire volume was produced by **our
own agents looping**; there was no human in the thread. This is the same failure
class as #855 (comment storm) and #916 (trigger storm), on a new surface.

No human noticed for four days.

---

## Root cause — two interacting loops

### Loop A — self-mention comment storm (dominant; 93.6% of all comments)

The `pr-review` cascade posts an acknowledgement comment that **@-mentions the bot
itself**:

> `<!-- pr-review-agent mention-ack -->`
> `@donpetry-bot I'm on it — starting a fresh review now…`

That self-mention is an `issue_comment: created` event, so the mention listener
(`pr-review-mention.yml` → `pr-review-mention-reusable.yml`) interpreted it as a
review request and re-triggered the cascade → another identical ack. **1,481 of
1,582 comments were this one byte-identical comment, at a ~9s cadence for ~4.5h**
on 2026-06-24. The bot was talking to itself.

### Loop B — dev-lead autofix commit storm (the 378 commits)

Each `dev-lead-fix-*` push re-fired the cascade on `synchronize`; each review
re-triggered `dev-lead`. `[skip ci-relay]` suppressed the **CI** relay but **not**
the **review** re-trigger, and each fixup is a new SHA so same-SHA idempotency
(#899) didn't help. The autofix engine **re-appended** function definitions
instead of replacing them — **14 functions defined 2–4×**, one file bloated to
2,513 lines before a manual cut to 1,454. The loop was actively *corrupting* the
code, not converging.

### The one guard that fired was defeated

The #467 3-cycle cap escalated once — but its documented re-engage path was
*"mention the bot (`@donpetry-bot review`) for an immediate re-review,"* which is
exactly what the self-mention ack does. **A safety cap whose reset is reachable by
the runaway agent is not a cap.**

---

## Why every existing guard let it through

| Guard | Why it didn't stop #860 |
|---|---|
| `MAX_REVIEW_CYCLES=3` (`scripts/lib/review-cycle.sh`, #467) | Fired once, then re-armed by the bot's own self-mention; also reset on *machine* approvals |
| `MAX_FAIL_ATTEMPTS=2` (`scripts/dev-lead-fix-ci.sh`) | Counts engine *failures* only; succeeding fixups that push commits increment nothing |
| `auto-rebase-retry` `MAX_ATTEMPTS=3`, sweep `MAX_DISPATCH=20` | Per-run / per-tick, not per-PR-lifetime |
| `concurrency: cancel-in-progress` | Bounds parallelism, not sequential iteration count |
| same-SHA idempotency (#899) | Every fixup is a new SHA |
| `dev-lead-retry.yml` (every 2h) | **Amplifier** — re-ignites stalled loops |

Nothing bounded **total automated activity on one PR over its lifetime**, and
**no guard's reset required a human.**

---

## Learnings

1. **An agent must never be triggered by its own output.**
2. **A safety cap whose reset is reachable by the runaway is not a cap** — resets
   must be human-gated.
3. **Bound the work item (the PR), not just each worker script.**
4. **Count actions, not just failures** — success can loop too.
5. **A new SHA is not new intent** — SHA-keyed idempotency can't break a fixup loop.
6. **Re-trigger crons amplify runaways** — they must check a stop condition before
   re-dispatching.
7. **No human noticed for four days** — detection must be pushed, not pulled.

---

## Fixes

This work spans two repos.

### `petry-projects/.github-private` (this repo) — P0

- **Human-gated cap reset** (`scripts/lib/review-cycle.sh`): only a *human*
  approval (a review with `state=APPROVED` by a non-bot author) or a human
  escalation resets the cycle cap. The cascade's own approval marker and machine
  approvals (`repair-pr-approvals`, bot approvals) no longer reset it. The
  re-engage copy in `scripts/review-one-pr.sh` no longer offers "mention the bot"
  as an automated escape hatch — only a human removing `needs-human-review`.
- **Per-PR automated-churn circuit breaker** (`scripts/lib/pr-automation-budget.sh`):
  `compute_pr_automation_cycles` / `pr_budget_exhausted` count agent-authored
  commits + review cycles + acks **since the last human interaction**; default
  `MAX_PR_AUTOMATION_CYCLES=10` (env-overridable). Consulted by
  `scripts/dev-lead-fix-reviews.sh`, `scripts/dev-lead-fix-ci.sh`, and
  `scripts/review-one-pr.sh` before any automated write. On exhaustion it **stops
  all automated writes**, adds `needs-human-review`, **disables auto-merge**, and
  posts **one** deduped escalation (marker `<!-- pr-automation-budget exhausted -->`).
  Re-engagement is human-gated. `FORCE_REVIEW` (mention-triggered) does **not**
  bypass this budget.

### `petry-projects/.github` (org repo) — P0, separate PR

- **Kill the self-trigger** in `pr-review-mention-reusable.yml`: ignore mention
  events authored by the bot itself and any comment carrying a
  `<!-- pr-review-agent … -->` marker; the ack comment must not literally
  `@`-mention `donpetry-bot` (plain text fires no mention webhook). The
  `.github-private` thin-caller stub (`pr-review-mention.yml`) cannot carry this
  logic (its triggers/permissions are fixed per AGENTS.md), so this half lands in
  the org reusable. Land org-first so the stub never assumes undeployed behavior.

### Follow-ups (P1/P2)

- P1: `dev-lead-retry.yml` / `pr-review-sweep.yml` skip PRs carrying the
  exhausted / `needs-human-review` marker before re-dispatching; post at most one
  exhaustion notice per advisory engine per run.
- P2: runaway-PR detection in `daily-pr-review-health` / `scripts/fleet_monitor.sh`
  (flag open PRs over soft thresholds: >50 commits, >200 comments, >N agent
  cycles, or open >48h with active agent churn); prefer rebase/squash over
  repeated `merge main` for agent branches.
