# 0012. The maintainer comment gate's exemption set

## Status

proposed

## Context

Issue #1813 redesigned pr-review's maintainer-comment gate
(`scripts/lib/maintainer-comment-gate.sh`). Its scope is **every PR issue
comment**: each one blocks approval until dev-lead posts a verified disposition
and the harness minimizes the comment `RESOLVED`. The only exclusions were our
own automation's replies, recognised by login or registered marker. #1918 later
added registered clean info-status bot comments.

ADR-0008 has the maintainer, dev-lead and the personas all post as `don-petry`.
So the gate cannot tell a finding from the owner's own words, and three kinds of
comment held `undispositioned-pr-comment` with nothing able to clear them
(defect 4 of [#2173](https://github.com/petry-projects/.github-private/issues/2173),
tracked as [#2209](https://github.com/petry-projects/.github-private/issues/2209)):

- the owner's `@donpetry-bot please review` comment, so each re-request added
  one more blocker to the review it asked for. On `petry-projects/.github` PR
  1276, two of the four blockers were review requests;
- the `<!-- auto-rebase-conflict: … -->` sentinel, whose marker was not
  registered. The conflict it reports already blocks the merge;
- an owner steering comment.

The solution-architect advisory on #2173 and the maintainer's ruling
(2026-10-10) settle the design. Exemptions are by registered marker or by one
exact whole-body form, nothing looser. ADR-0004 keeps judgment out of
classifiers, so a pure rule cannot tell steering from a finding.

## Decision

We will narrow #1813's "every PR issue comment" scope to every PR issue comment
**except** this exemption set, and no other:

1. **Our bot login** (`BOT_USER`, default `donpetry-bot`, with or without the
   `[bot]` suffix).
2. **A registered automation marker** in the body
   (`_MAINTAINER_GATE_AGENT_MARKERS`): `pr-review-agent`, `pr-review-claim`,
   `persona:`, `dev-lead` (including `dev-lead:comment-disposition`),
   `dependency-advisory`, `maintainer-resolve`, and `auto-rebase-conflict:`.
3. **A review request**: the author association is `OWNER`, `MEMBER` or
   `COLLABORATOR`, and the whole trimmed body is the bot mention (`@<bot user>`),
   optionally followed by `please review` (case-insensitive, optional final `.`
   or `!`), optionally followed by the Claude Code footer (a `---` rule and the
   line `_Generated by [Claude Code](<url>)_`). The match is anchored at both
   ends, so any other text keeps the comment in scope.
4. **The maintainer opt-out**: the author association is `OWNER`, `MEMBER` or
   `COLLABORATOR`, and the body carries `<!-- maintainer:not-a-finding -->`.
   From any other author the marker does nothing.
5. **A registered clean info-status bot comment** (#1918): a registered
   reviewer source whose body matches its `info_status_pattern` and carries no
   finding-bearing section (#2008).

We will never exempt by author login alone, because `don-petry` is also the
account dev-lead and the personas post from. A steering comment stays in scope
unless the maintainer opts it out. Fail closed holds: a missing
`authorAssociation` grants neither exemption 3 nor 4, and an unreadable
snapshot still blocks.

We will keep exemptions 1–4 in one definition (`_MAINTAINER_GATE_SCOPE_JQ_DEFS`)
used by both the gate and dev-lead's candidate filter
(`maintainer_gate_open_comment_ids`, called by `resolve_dispositioned_comments`),
so the harness never tries to disposition a comment the gate does not count.
Bats tests cover the definition (ADR-0004).

## Consequences

- A review request no longer blocks the review it asks for, and the conflict
  sentinel no longer blocks twice for one conflict.
- The review-request form is strict. "@donpetry-bot, please review",
  "@donpetry-bot please take another look" or a request with a note attached
  still blocks and needs a disposition or the opt-out marker. A looser match
  would let a finding hide behind a mention.
- The opt-out marker is a trust grant to every OWNER/MEMBER/COLLABORATOR. A
  collaborator can clear their own comment from the gate without a disposition,
  so anything they post with the marker is not checked.
- Steering still costs the maintainer one marker per comment. Telling steering
  from a finding automatically would need judgment, which ADR-0004 keeps out of
  the classifiers.
- The sentinel's exemption relies on the merge conflict blocking the merge by
  itself. If GitHub ever let a conflicted PR merge, the comment would no longer
  be a backstop.
